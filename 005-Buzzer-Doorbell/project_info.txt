PROJECT NAME: 005 - Buzzer Doorbell
PROJECT IDEA: A push button triggers a passive buzzer to play a classic two-note "ding-dong" doorbell chime, with a guard that stops the sound from repeating while the button is held.
HOW IT WORKS: The button sits on pin 2 using the internal pull-up, so pressing it pulls the pin LOW. When a press is detected, tone() plays 523 Hz for 300 ms, a short gap follows, and then 392 Hz plays for 500 ms before noTone() silences the buzzer. A boolean flag is set so the chime only fires once per press, and it is cleared as soon as the button is released.
ADVANTAGES:
- A passive buzzer plus tone() needs no sound files or extra libraries.
- The repeat guard prevents a held button from hammering out chimes.
- Note frequencies and durations are named constants, so the melody is easy to retune.
- Push button to GND with INPUT_PULLUP needs no external resistor.
- Serial messages confirm each chime without listening for it.
REAL-WORLD USES:
- Doorbells, entry chimes, and shop "customer entered" alerts.
- Appliance completion beeps and finished-cycle tones.
- Warning buzzers on machines and hobby projects.
- Quiz and game show buzzers.
- Simple musical gadgets and electronic greeting cards.
WHAT YOU LEARN:
- Producing sound with tone() and noTone() and what frequency in Hz means.
- Choosing durations to shape a simple melody.
- Using a boolean flag as a repeat/hold guard.
- Reading a button with INPUT_PULLUP logic.
- Combining sound output with input handling in one loop.
FUTURE SCOPE: The melody can be expanded into multi-note tunes, different chimes for different rooms, or a volume control using PWM.
POSSIBLE UPGRADES:
- Play a longer melody such as Westminster chimes.
- Add a second button for a different ring tone.
- Use an active buzzer plus a relay for a louder mechanical bell.
- Require a PIN of button presses before the chime sounds.
